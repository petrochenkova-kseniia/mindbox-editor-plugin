# Пинг кейсов

Скилл для управления пингами по кейс-проектам. Помогает генерировать сообщения менеджерам, отслеживать статусы и вести историю пингов.

## Таблица проектов

ID: `1QFZ7p9uezz5HNOV_ecR2RukiZR-FsSKkKTS4x8eArBA`
Листы: `Midmarket`, `Enterprise`

Колонки:
- A — проект
- B — менеджер
- C — команда
- D — когда пишем кейс (H1 / H2 / Не напишем / пусто)
- E — комментарий (история пингов и статусов)
- F — следующий пинг (дата DD.MM.YYYY)
- G — статус («жду ответа» / «ответил» / пусто)

## Сценарий 1: Сгенерировать сообщения для пингов

Когда пользователь говорит «сгенерируй сообщения» / «пинги на сегодня» / «что пинговать»:

### Шаг 1: Прочитать таблицу

Прочитать оба листа таблицы через Google Sheets API. Определить проекты, которые нужно пинговать сегодня (дата в колонке F = сегодня или раньше).

Если пользователь назвал конкретные проекты — работать только с ними.

Проекты со статусом «Не напишем» в колонке D — игнорировать.

### Шаг 2: Прочитать историю комментариев

Для каждого проекта прочитать колонку E (Комментарий) — в ней история взаимодействий с менеджером.

### Шаг 3: Сгенерировать сообщения

Для каждого проекта написать сообщение менеджеру.

**Правила:**
- Обращение неформальное, по имени в разговорной форме: Маш, Марин, Аня, Трофим — не «Мария», не «Анастасия»
- Ссылаться на предыдущий разговор или контекст: «ты в феврале писала», «ты говорила», «вы договорились»
- Не пересказывать менеджеру его же слова — только ссылка на суть + вопрос вперёд
- Заканчивать конкретным вопросом или предложением помочь
- Без вступлений-штампов, 2–3 предложения максимум
- Если повторный пинг (статус «жду ответа») — чуть настойчивее, упомянуть что уже спрашивала

**Примеры хороших сообщений:**

«Ана Роса, привет! Ты в феврале писала, что Poisondrop, Umschool, youwanna в целом готовы на кейс, надо прокопать бриф. Нужна с этим помощь?»

«Маш, я у тебя ещё хотела уточнить насчёт СпортМарафона. Ты говорила, что можно сделать кейс с ОПА. Что для этого нужно и когда к ним стоит стучаться?»

### Шаг 4: Вывести черновики

Вывести для каждого проекта:
```
**Проект:** Benetton
**Менеджер:** Marina Kolganko
**Черновик:**
[текст сообщения]
---
```

После всех черновиков написать:
«Когда отправишь — скажи, я проставлю статусы и даты следующих пингов.»

### Шаг 5: После отправки

Когда пользователь подтвердил отправку — для каждого проекта:
1. Колонка G → «жду ответа»
2. Колонка F → сегодня + 3 дня (дата следующего пинга)

## Сценарий 2: Обновить статус после ответа менеджера

Когда пользователь говорит «менеджер ответил» / «обнови статус» / «Marina ответила»:

1. Уточнить: что ответил менеджер и когда следующий пинг (если пользователь не указал)
2. Обновить таблицу:
   - Колонка E — заменить комментарий на новый: «ДД.ММ — краткое резюме ответа»
   - Колонка G → «ответил»
   - Колонка F → дата следующего пинга

Дату следующего пинга выбирать исходя из контекста:
- Собирают цифры / готовятся → через 1–2 недели
- Нужно время на согласование → через 2–3 недели
- Активно работают над кейсом → через 3–4 недели

## Логика пингов

- После каждого пинга: статус → «жду ответа», следующий пинг = сегодня + 3 дня
- Если менеджер ответил: обновить комментарий, статус → «ответил», сдвинуть дату вперёд
- Если через 3 дня нет ответа: проект попадает в секцию «Нет ответа — пнуть снова»
- Формат комментария: при каждом апдейте заменять текст целиком. Только дата и новый статус: «18.03 — клиент собирает цифры, постучаться в мае»
- Комментарии не дописывать через «|» — каждый раз полная замена
